## B2 — reorder/insert/remove churn on a memo-stable keyed list (task 5.0 baseline)

App: `src/examples/bench/keyed-table.ts` — demo `keyed-table`; scenario
`b2-keyed-churn` in `tests/e2e/bench-scenarios-b2.ts`; results
`benchmarks/results/b2-keyed-churn.json`.

Setup: "Build 1000" (untimed drawn setup — 1,000 memo-stable rows keyed by
id via `components.memo`), then a cycling churn set, one op per timed
sample: **Swap Rows** (reorder), **Insert first** (the mid-list insert — a
fresh row at position 0 shifts every subsequent row, the case the keyed
splice exists to kill; the tail-append case is M1's already-cheap B3 anchor
and is deliberately NOT the insert vehicle), **Remove 10** (remove), and
**Replace 10%** (the relabel control — rows at and after each relabelled
index change content, so they must rebuild under either rule). 8 timed ops
= two churn cycles, +1 untimed warmup op. `countMutations: true` — the
MutationObserver counts mutated elements with added/removed subtrees
EXPANDED before counting (the rinv protocol), so wrapper churn cannot hide
behind a single container swap.

Baseline BEFORE the keyed splice mechanism (PR-01): commit `14a2f0c11`
(main, add-keyed-dom-reconciliation §1 landed — keyed() declaration + pure
reconcile plan, painter NOT yet keyed). Chrome 156.0.8078.4, CDP CPU
throttled ×4, 3 runs × 8 ops (+1 untimed warmup op), production bundle.

| metric | value |
|---|---|
| wall-clock median | 259.22 ms/op |
| wall-clock p25 / p75 / p90 | 233.32 / 293.66 / 328.90 ms |
| DOM mutations per op | **3 020–3 023, near-identical across all 24 ops** |

Reading: every churn op — even the two-row Swap — deterministically touches
~3 021 DOM nodes. The per-keyed-row cost is wrapper churn: today a keyed
wrapper is fresh per derive, falls through the unknown-node fallback, and
rebuilds its wrapper div per row per frame (the inner memo-stable span
splices through M1's positional rule, so CONTENT is never stale — the cost
is purely structural: ~3 fresh/moved nodes per row per frame). Wall-clock
variance is frame-timing noise; the mutation count is the invariant the
keyed re-run must move. Task 5.1 target: mutations drop to the structural
delta (a swap moves 2 row elements, an insert-first builds 1 fresh row and
moves 0, a remove drops the removed rows), with focus/selection
preservation verified in a real browser; the B3 streaming anchor and the
pinned state-equivalence contract stay green in both runs.
